# 1.5 Static and Dynamic Data Structures

Data structures can also be classified by **how they use memory**: whether their size is fixed or can change while the program runs.

```
Data Structures
├── Static   → fixed size        (Array)
└── Dynamic  → size can change   (Linked List, Stack/Queue using linked list, Tree, Graph)
```

---

# Static Data Structure

In a static data structure, the **size of the structure is fixed**.

- The **content** can be modified, but **without changing the memory space** allocated to it.
- Static data structures, such as an **array**, have a fixed size and are **allocated at compile time**.
- The memory size **cannot be changed** during program execution.

```c
int arr[5];   // size is fixed at 5. It can't grow or shrink while the program runs
```

You can change *what's inside* (`arr[0] = 10;`), but you can't make the array bigger than 5.

### Advantages of Static Data Structure

**a. Fast access time**
Memory is allocated at compile time and the size is fixed, which makes accessing elements simple. Elements sit next to each other in memory, so any element can be reached directly using its index.

**b. Predictable memory usage**
Since memory allocation is fixed at compile time, the programmer can precisely predict how much memory the program will use.

**c. Ease of implementation and optimization**
Because the size is fixed, there's no need to handle resizing. This makes the structure easier to build and easier for the compiler to optimize.

**d. Efficient memory management**
Memory is set aside once, before the program runs, so there's no extra work of allocating and freeing during execution. There's also less risk of problems like memory leaks.

**e. Simplified code**
With a fixed size, the code stays short and straightforward. There's no need to write extra logic for allocating, resizing, or freeing memory.

### Limitations

- **Memory waste:** if you reserve a bigger size than needed, the unused space is wasted.
- **Overflow:** if you reserve too little, you run out of space and can't add more.
- **Can't be resized** during execution.

---

# Dynamic Data Structure

In a dynamic data structure, the **size of the structure is not fixed** and can be modified during the operations performed on it.

- The memory size **can be changed** during program execution.
- Memory can be **dynamically allocated or deallocated** as needed.

In C, this is done using functions from `<stdlib.h>`:

| Function | What it does |
|----------|--------------|
| `malloc()` | Allocates a block of memory |
| `calloc()` | Allocates memory for multiple elements and sets them to 0 |
| `realloc()` | Changes the size of already allocated memory |
| `free()` | Releases (deallocates) memory |

```c
int *arr = (int *) malloc(5 * sizeof(int));        // allocate space for 5 integers
arr = (int *) realloc(arr, 10 * sizeof(int));      // grow it to 10 while running
free(arr);                                         // give the memory back
```

**Linked lists** are the classic example. Each new node is created only when needed, and removed nodes are freed.

### Advantages of Dynamic Data Structure

**a. Flexibility**
The size can grow or shrink as the program needs. You don't have to know the amount of data in advance.

**b. Reduced memory waste**
Memory is used only for the data that's actually there. When data is removed, that memory can be released, so nothing is sitting unused.

**c. Improved performance for some operations**
Some operations become faster. For example, inserting or deleting in a linked list only needs a few links to be changed, while an array needs elements to be shifted.

**d. Simplified code**
There's no need to guess a maximum size or write workarounds like copying everything into a bigger array when it gets full. The structure adjusts itself to the data.

### Limitations

- **Extra memory** is needed to store pointers (addresses of other nodes).
- **Slower access:** elements usually have to be reached sequentially, not by direct index.
- **More careful handling:** forgetting to free memory causes **memory leaks**, and wrong pointer use can crash the program.

---

# Static vs Dynamic: Side-by-Side

| Basis | Static Data Structure | Dynamic Data Structure |
|-------|-----------------------|------------------------|
| **Size** | Fixed | Not fixed, can change during execution |
| **Memory allocation** | At **compile time** | At **run time** |
| **Changing memory size** | Not possible during execution | Possible. Memory can be allocated or deallocated |
| **Access time** | Fast (direct access using index) | Usually slower (often sequential) |
| **Memory usage** | Predictable, but can be wasted | Flexible, used as needed (plus pointer overhead) |
| **Example** | Array | Linked List, Tree, Graph |

---

# Quick Revision

- **Static:** fixed size, allocated at compile time, can't change size during execution. Example: array.
- **Static advantages:** fast access time, predictable memory usage, easy implementation and optimization, efficient memory management, simplified code.
- **Dynamic:** size not fixed, can change during execution, memory is allocated or deallocated as needed. Example: linked list.
- **Dynamic advantages:** flexibility, reduced memory waste, improved performance for some operations, simplified code.
- Static gives **speed and predictability**. Dynamic gives **flexibility**.

# 1.4 Classification of Data Structures

Data structures can be generally classified into **primitive** and **non-primitive** data structures.

```
Data Structures
├── Primitive
│   └── Integer, Real, Character, Boolean
└── Non-Primitive
    ├── Linear
    │   └── Array, Linked List, Stack, Queue
    └── Non-Linear
        └── Tree, Graph
```

## Primitive Data Structures

Basic data structures that **cannot be further divided** are called **primitive data structures**.

Examples: **integer, real, character, boolean**

## Non-Primitive Data Structures

Data structures that can be used for **other complex storages** are called **non-primitive data structures**. They are built using the primitive ones.

Non-primitive data structures are classified into **linear** and **non-linear**.

| | Linear | Non-Linear |
|---|--------|------------|
| **Idea** | Elements form a **sequence** (one after another) | Elements are **not arranged in a sequence** |
| **Examples** | Array, Linked List, Stack, Queue | Tree, Graph |

# Linear Data Structures

## Arrays

An array is a collection of variables of **similar type** that are referenced by a **common name**.

- Each data item in an array is called an **element**.
- Elements are stored in **continuous memory locations**.
- Elements are accessed using an **index value** (also called a **subscript**).
- The index of the first element is **0**, and the index of the last element is **N-1** (for an array of size N).

```
Index:    0    1    2    3    4
        ┌────┬────┬────┬────┬────┐
arr  =  │ 10 │ 20 │ 30 │ 40 │ 50 │
        └────┴────┴────┴────┴────┘
```

So for `arr` above, `arr[0]` is `10` and `arr[4]` is `50`.

### Declaration of array

Syntax for declaring an array of size n:

```c
datatype arrayname[size];
```

Example:

```c
int arr[7];
```

### Initialization of array

An array can be initialized **during declaration**:

```c
int arr[7] = {1, 2, 3, 4, 5, 6, 7};
```

We can also initialize an array **without specifying the size**. The compiler counts the elements for us:

```c
int arr[] = {1, 2, 3, 4, 5};
```

> **Extra point:** If you give fewer values than the size (like `int arr[5] = {1, 2};`), the remaining elements are set to `0`.

### Representation of array (memory)

Suppose the **base address** of the array `arr` is `1000`. Then:

- address of `arr[0]` = 1000
- address of `arr[1]` = 1002
- address of `arr[2]` = 1004

This is because the size of `int` is **2 bytes** (in this example).

```
Address:   1000   1002   1004   1006
         ┌──────┬──────┬──────┬──────┐
         │ arr0 │ arr1 │ arr2 │ arr3 │
         └──────┴──────┴──────┴──────┘
```

General formula:

```
Address of arr[i] = Base Address + (i × size of one element)
```

> **Note:** On most modern compilers, `int` is **4 bytes**, so `arr[1]` would be at 1004 and `arr[2]` at 1008. The 2-byte size is from older compilers like Turbo C. The formula stays the same, only the element size changes. For the exam, follow the size your syllabus or question gives.

### One dimensional array

A linear or one dimensional array is the **simplest type** of data structure. It is a continuous memory location that stores the **same type of data** under a common name.

### Two dimensional array

A multidimensional array can be considered as an **array of arrays**, or as a **matrix** consisting of **rows and columns**.

Syntax for declaring a two dimensional array:

```c
datatype arrayname[sizeofrows][sizeofcolumns];
```

Example:

```c
int arr[3][3];
```

Initialization example:

```c
int arr[2][3] = { {1, 2, 3},
                  {4, 5, 6} };
```

Here `arr[1][2]` is `6` (row 1, column 2, counting from 0).

```
          Col 0  Col 1  Col 2
Row 0   │   1      2      3   │
Row 1   │   4      5      6   │
```

## Linked List

A linked list is a collection of data elements whose **order is not given by their physical location in memory**. It consists of **nodes** that contain data and a link to the next node.

A node has **two parts**:

1. **Data part:** the data is stored here
2. **Link / Address part:** stores the **address of the next node**

```
 ┌──────┬──────┐    ┌──────┬──────┐    ┌──────┬──────┐
 │ Data │ Next │ ─► │ Data │ Next │ ─► │ Data │ NULL │
 └──────┴──────┘    └──────┴──────┘    └──────┴──────┘
   Node 1              Node 2              Node 3
```

The last node's link part is `NULL`, which means "nothing comes after this".

A node in C looks like this:

```c
struct Node {
    int data;
    struct Node *next;
};
```

### Doubly Linked List

A doubly linked list, or **Two Way Linked List**, is a type of linked list that contains a pointer to the **next node** as well as the **previous node** in the sequence.

Each node in a doubly linked list consists of:

a. **data:** data item
b. **prev:** address of the previous node
c. **next:** address of the next node

```
        ┌──────┬──────┬──────┐     ┌──────┬──────┬──────┐     ┌──────┬──────┬──────┐
NULL ◄─ │ prev │ Data │ next │ ◄─► │ prev │ Data │ next │ ◄─► │ prev │ Data │ next │ ─► NULL
        └──────┴──────┴──────┘     └──────┴──────┴──────┘     └──────┴──────┴──────┘
            Node 1                     Node 2                     Node 3
```

The `prev` of the first node and the `next` of the last node are `NULL`.

A node in C looks like this:

```c
struct Node {
    int data;
    struct Node *prev;
    struct Node *next;
};
```

**Why it's useful:**

- You can move **both forward and backward** through the list.
- Deleting a node is easier when you already have a pointer to it, because the node knows its own previous node.

**Trade-off:** each node needs **extra memory** for the `prev` pointer.

---

### Circular Linked List

A circular linked list is a list in which the **last node points back to the first node**, forming a circle. There is **no NULL pointer** at the end.

```
 ┌──────┬──────┐    ┌──────┬──────┐    ┌──────┬──────┐
 │ Data │ Next │ ─► │ Data │ Next │ ─► │ Data │ Next │ ─┐
 └──────┴──────┘    └──────┴──────┘    └──────┴──────┘  │
   ▲                                                     │
   └─────────────────────────────────────────────────────┘
```

**Why it's useful:**

- You can start from **any node** and still reach every other node.
- It's good for things that repeat in a loop, like **round-robin scheduling** (the CPU gives each process a turn, then goes back to the first one).

**Things to watch out for:**

- Since there's no `NULL` at the end, a normal "loop until NULL" traversal would **never stop**. You stop when you come back to the node you started from.
- A circular list can be built from a singly linked list or a doubly linked list.

---

### Types of Linked List: Quick Comparison

| Type | Pointers in each node | End of the list |
|------|-----------------------|-----------------|
| **Singly** (the basic one) | `next` | Last node's `next` is `NULL` |
| **Doubly** | `prev` and `next` | First `prev` and last `next` are `NULL` |
| **Circular** | `next` (or `prev` and `next`) | Last node points back to the first, no `NULL` |

## Stack

A stack follows the **LIFO (Last In First Out)** system. It is a linear data structure in which **insertion (PUSH)** and **deletion (POP)** are restricted to **one end point**, called **TOP**.

```
        │  30  │  ◄── TOP (last pushed, first to come out)
        │  20  │
        │  10  │
        └──────┘
```

- **PUSH:** adds an element at the top
- **POP:** removes the element from the top

> **Real-life example:** a stack of plates. You put a plate on top and take a plate from the top.

---

## Queue

A queue follows the **FIFO (First In First Out)** principle. Insertion can take place **only at one end called Rear**, and deletion can take place **only at the other end called Front**.

```
  Front                          Rear
    ▼                              ▼
  ┌────┬────┬────┬────┐
  │ 10 │ 20 │ 30 │ 40 │ ◄── new elements join here
  └────┴────┴────┴────┘
  ▲
  elements leave from here
```

> **Real-life example:** a line at a ticket counter. The first person to join the line is the first one served.

# Non-Linear Data Structures

## Tree

Some data contains a **hierarchical relationship** between various elements. This data is represented in the form of a **rooted tree graph**, or simply a **tree**.

```
          A          ◄── Root
         / \
        B   C        ◄── Children of A
       / \
      D   E          ◄── Leaves (no children)
```

> **Real-life examples:** a family tree, a company's org chart, the folder structure on your computer.

## Graph

Sometimes data contains relationships that are **not hierarchical** in nature. These types of relationships can be represented in the form of a **graph data structure**.

```
    A ─── B
    │   ╱ │
    │  ╱  │
    C ─── D
```

> **Real-life examples:** a social network (people connected to people), a road map (cities connected by roads).

# Difference Between Arrays and Linked List

| Basis | Arrays | Linked List |
|-------|--------|-------------|
| **Memory location** | Data can be stored **only in continuous** memory locations | Data can exist at **non-continuous** addresses |
| **Size** | **Fixed**, can't be altered at runtime | Can be **changed at runtime** |
| **Access** | **Random access** is allowed (jump straight to any index) | Elements must be accessed **sequentially** (start from the first node) |
| **Memory usage** | Memory equal to the **upper limit** must be allocated, even if not all of it is used | **Extra memory** is required to store the pointers |
| **Insertion / Deletion** *(extra)* | Slow, since elements may need to be shifted | Easy, only the links need to change |

# Quick Revision

- Data structures are classified as **primitive** (integer, real, character, boolean) and **non-primitive**.
- Non-primitive is split into **linear** (elements in a sequence) and **non-linear** (not in a sequence).
- **Linear:** Array, Linked List, Stack, Queue. **Non-linear:** Tree, Graph.
- **Array:** same-type elements, continuous memory, accessed by index from `0` to `N-1`.
- **Linked list:** nodes with a data part and a link part, so order doesn't depend on physical memory location.
- **Stack:** LIFO, with PUSH and POP at the TOP.
- **Queue:** FIFO, insertion at Rear and deletion at Front.
- **Tree:** hierarchical relationship. **Graph:** non-hierarchical relationship.

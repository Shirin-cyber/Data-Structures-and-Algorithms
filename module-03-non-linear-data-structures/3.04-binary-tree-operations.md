# 3.4 Binary Tree Operations

# 1. Binary Tree Traversal

**Traversing** a tree means **visiting every node exactly once**.

A binary tree can be traversed in **three different ways**, namely **Preorder, Postorder and Inorder**. The **order in which the nodes are visited** differs between these techniques.

```
Binary Tree Traversal
├── a. Inorder     (Left → Root → Right)
├── b. Preorder    (Root → Left → Right)
└── c. Postorder   (Left → Right → Root)
```

> **The big idea:** in all three, the **left subtree is always done before the right subtree**. The only thing that changes is **when the root is processed**:
> - **Pre**order: root **first** (pre = before)
> - **In**order: root **in the middle** (in = between)
> - **Post**order: root **last** (post = after)

### The tree used in the examples

```
          A
         / \
        B   C
       / \   \
      D   E   F
```

Here `R` in the steps below means the **root of the tree (or subtree)** we're currently working on. Every traversal is **recursive**: when it says "traverse the left subtree", we apply the same three steps to that smaller tree.

---

## a. Inorder Traversal

The traversal operation is done by:

1. **Traverse the left subtree** of R
2. **Process the root** R
3. **Traverse the right subtree** of R

**Result for the example tree: `D B E A C F`**

How it works, step by step:

```
Inorder(A)
├── Inorder(B)                  ← left subtree of A
│   ├── Inorder(D)              ← left of B
│   │     (D has no left)  → process D
│   │     (D has no right)
│   ├── process B               ← root B
│   └── Inorder(E)              ← right of B
│         process E
├── process A                   ← root A
└── Inorder(C)                  ← right subtree of A
    ├── (C has no left)
    ├── process C
    └── Inorder(F)
          process F

Output:  D  B  E  A  C  F
```

### Algorithm (recursive)

```
Inorder(R)
Step 1: If R = NULL, then return
Step 2: Inorder(left subtree of R)
Step 3: Process R (print its data)
Step 4: Inorder(right subtree of R)
```

---

## b. Preorder Traversal

Preorder traversal is also known as **Depth-first traversal**. The traversal operation is done by:

1. **Process the root** R
2. **Traverse the left subtree** of R
3. **Traverse the right subtree** of R

**Result for the example tree: `A B D E C F`**

```
Preorder(A)
├── process A                   ← root first
├── Preorder(B)
│   ├── process B
│   ├── Preorder(D) → process D
│   └── Preorder(E) → process E
└── Preorder(C)
    ├── process C
    └── Preorder(F) → process F

Output:  A  B  D  E  C  F
```

> **About "depth-first":** all three traversals go **deep** into the tree (down one branch) before moving across to the next branch, so strictly they are all depth-first. Preorder is the one that follows the usual depth-first order starting from the root, which is why it's often the one called depth-first traversal. Use whichever wording your syllabus uses.

### Algorithm (recursive)

```
Preorder(R)
Step 1: If R = NULL, then return
Step 2: Process R (print its data)
Step 3: Preorder(left subtree of R)
Step 4: Preorder(right subtree of R)
```

---

## c. Postorder Traversal

The operation is done by:

1. **Traverse the left subtree** of R
2. **Traverse the right subtree** of R
3. **Process the root** R

**Result for the example tree: `D E B F C A`**

```
Postorder(A)
├── Postorder(B)
│   ├── Postorder(D) → process D
│   ├── Postorder(E) → process E
│   └── process B               ← B comes after its children
├── Postorder(C)
│   ├── Postorder(F) → process F
│   └── process C
└── process A                   ← root last

Output:  D  E  B  F  C  A
```

### Algorithm (recursive)

```
Postorder(R)
Step 1: If R = NULL, then return
Step 2: Postorder(left subtree of R)
Step 3: Postorder(right subtree of R)
Step 4: Process R (print its data)
```

---

## Comparing the Three

| Traversal | Order | When is the root processed? | Result for the example tree |
|-----------|-------|-----------------------------|-----------------------------|
| **Inorder** | Left, Root, Right | Between the subtrees | `D B E A C F` |
| **Preorder** | Root, Left, Right | Before the subtrees | `A B D E C F` |
| **Postorder** | Left, Right, Root | After the subtrees | `D E B F C A` |

## Traversals in C 

```c
struct node {
    char data;
    struct node *left;
    struct node *right;
};

void inorder(struct node *root) {
    if (root == NULL) return;
    inorder(root->left);
    printf("%c ", root->data);
    inorder(root->right);
}

void preorder(struct node *root) {
    if (root == NULL) return;
    printf("%c ", root->data);
    preorder(root->left);
    preorder(root->right);
}

void postorder(struct node *root) {
    if (root == NULL) return;
    postorder(root->left);
    postorder(root->right);
    printf("%c ", root->data);
}
```

The three functions are identical except for **where the `printf` line sits**.

## Connection to Expression Trees 

Remember the expression tree for `(a + b) * c` from 3.2?

```
        *
       / \
      +   c
     / \
    a   b
```

Traversing it gives the three notations from Polish notation:

| Traversal | Result | Notation |
|-----------|--------|----------|
| **Inorder** | `a + b * c` *(brackets are lost)* | Infix |
| **Preorder** | `* + a b c` | Prefix |
| **Postorder** | `a b + c *` | Postfix |

> There's also a fourth way, **level order traversal**, which visits the nodes level by level, from top to bottom and left to right. It uses a **queue**. For the example tree, it gives `A B C D E F`.

# 2. Binary Tree Insertion

Insertion means **adding a new node** to the tree. How it's done depends on the kind of binary tree, so both common versions are given below.

---

## a. Insertion in a General Binary Tree

In a general binary tree there's no rule about where values go, so the new node is placed at the **first empty position found, going level by level from top to bottom and left to right** (level order). This keeps the tree filled up neatly with no gaps.

### Steps

1. If the tree is empty, the new node becomes the **root**.
2. Otherwise, go through the tree **level by level**.
3. Find the first node that has an **empty left child or empty right child**.
4. Put the new node there (**left first**, then right).

### Example: insert `E`

```
Before:              After:

    A                    A
   / \                  / \
  B   C                B   C
 /                    / \
D                    D   E
```

Level order is `A, B, C, D`. A has both children. B has a left child (D) but its **right child is empty**, so `E` goes there.

### Algorithm

A **queue** is used to go through the tree level by level.

```
Step 1: Create a new node NEW with NEW -> DATA = ITEM
        and NEW -> LEFT = NEW -> RIGHT = NULL
Step 2: If ROOT = NULL
          Set ROOT = NEW and go to Step 5
Step 3: Add ROOT to the queue
Step 4: Repeat while the queue is not empty
          Remove a node TEMP from the queue
          If TEMP -> LEFT = NULL
              Set TEMP -> LEFT = NEW and go to Step 5
          Else
              Add TEMP -> LEFT to the queue
          If TEMP -> RIGHT = NULL
              Set TEMP -> RIGHT = NEW and go to Step 5
          Else
              Add TEMP -> RIGHT to the queue
Step 5: Stop
```

---

## b. Insertion in a Binary Search Tree (BST)

In a **binary search tree**, every value in the **left** subtree is **smaller** than the node and every value in the **right** subtree is **bigger**. So the new value has to go in the one correct place.

### Steps

1. Start at the **root**.
2. If the new value is **smaller** than the current node, go **left**. If it's **bigger**, go **right**.
3. Repeat until you reach an **empty spot** (`NULL`).
4. Insert the new node there.

### Example: insert `45`

```
Before:                         After:

          50                            50
         /  \                          /  \
       30    70                      30    70
      /  \   / \                    /  \   / \
    20   40 60  80                20   40 60  80
                                        \
                                         45
```

- `45 < 50` → go **left** to 30
- `45 > 30` → go **right** to 40
- `45 > 40` → go **right**, and that spot is empty → insert `45` here

### Algorithm (recursive)

```
Insert(ROOT, ITEM)
Step 1: If ROOT = NULL
          Create a new node with data ITEM and return it
Step 2: If ITEM < ROOT -> DATA
          Set ROOT -> LEFT = Insert(ROOT -> LEFT, ITEM)
Step 3: Else if ITEM > ROOT -> DATA
          Set ROOT -> RIGHT = Insert(ROOT -> RIGHT, ITEM)
Step 4: Return ROOT
```

> **Note:** BSTs normally don't allow duplicate values, so an item equal to an existing one is not inserted.

# 3. Binary Tree Deletion

Deletion means **removing a node** from the tree. The tricky part is what to do with the **children** of the deleted node, because we can't just leave them hanging.

---

## a. Deletion in a General Binary Tree

If we simply remove a node that has children, its subtrees get disconnected. So the trick is:

1. **Find** the node to delete.
2. Find the **deepest, rightmost node** in the tree (the **last node** in level order).
3. **Copy** that node's data into the node to be deleted.
4. **Delete** the deepest, rightmost node (it's a leaf, so it's easy to remove).

### Example: delete `B`

```
Before:                 After:

      A                     A
     / \                   / \
    B   C                 E   C
   / \                   /
  D   E                 D
```

- Level order is `A, B, C, D, E`, so the deepest rightmost node is `E`.
- Copy `E` into B's position, and remove the old `E` node.

### Algorithm

```
Step 1: If ROOT = NULL
          Print "Tree is empty" and go to Step 6
Step 2: Find the node KEY to be deleted
          If it is not found, print "Node not found" and go to Step 6
Step 3: Find the deepest rightmost node DEEPEST
        (the last node in level order)
Step 4: Set KEY -> DATA = DEEPEST -> DATA
Step 5: Delete the DEEPEST node
        (set its parent's pointer to it as NULL and free its memory)
Step 6: Stop
```

> **Special case:** if the tree has only one node (the root) and it's deleted, the tree becomes empty (`ROOT = NULL`).

---

## b. Deletion in a Binary Search Tree (BST)

After deleting a node, the tree must **still follow the BST rule**. There are **three cases**, depending on how many children the node has.

### Case 1: the node is a leaf (no children)

Simply **remove it**.

```
Delete 20:

          50                     50
         /  \                   /  \
       30    70               30    70
      /  \                      \
    20   40                      40
```

### Case 2: the node has one child

**Replace the node with its child.**

```
Delete 40 (its only child is 45):

       30                    30
      /  \                  /  \
    20   40       →       20    45
           \
            45
```

### Case 3: the node has two children

1. Find the node's **inorder successor**, which is the **smallest value in its right subtree**.
2. **Copy** that value into the node.
3. **Delete** the successor from the right subtree. It has at most one child, so this is Case 1 or Case 2.

```
Delete 50 (the root has two children):

          50                       60
         /  \                     /  \
       30    70        →        30    70
      /  \   / \               /  \     \
    20   40 60  80           20   40     80
```

The smallest value in 50's right subtree (70, 60, 80) is `60`. It replaces `50`, and the old `60` node is removed.

> You can also use the **inorder predecessor** (the **largest** value in the left subtree) instead. Either way works.

### Algorithm (recursive)

```
Delete(ROOT, KEY)
Step 1: If ROOT = NULL
          Return ROOT              (key not found)
Step 2: If KEY < ROOT -> DATA
          Set ROOT -> LEFT = Delete(ROOT -> LEFT, KEY)
Step 3: Else if KEY > ROOT -> DATA
          Set ROOT -> RIGHT = Delete(ROOT -> RIGHT, KEY)
Step 4: Else (this is the node to be deleted)
          Case 1: no child
              Free ROOT and return NULL
          Case 2: one child
              Set TEMP = the child of ROOT
              Free ROOT and return TEMP
          Case 3: two children
              Find SUCC = smallest node in the right subtree of ROOT
              Set ROOT -> DATA = SUCC -> DATA
              Set ROOT -> RIGHT = Delete(ROOT -> RIGHT, SUCC -> DATA)
Step 5: Return ROOT
```

# Quick Revision (additions)

- **Insertion in a general binary tree:** place the new node at the first empty position in level order (top to bottom, left to right).
- **Insertion in a BST:** compare with each node, go left if smaller and right if bigger, and insert at the first empty spot.
- **Deletion in a general binary tree:** copy the deepest rightmost node's data into the node to delete, then remove the deepest rightmost node.
- **Deletion in a BST:** three cases. **Leaf:** remove it. **One child:** replace it with the child. **Two children:** replace it with the inorder successor, then delete the successor.

## Quick Revision

- **Traversal** = visiting every node exactly once.
- **Inorder:** Left → Root → Right.
- **Preorder:** Root → Left → Right. Also known as depth-first traversal.
- **Postorder:** Left → Right → Root.
- In all three, left comes before right. Only the position of the root changes.
- Example tree: Inorder `D B E A C F`, Preorder `A B D E C F`, Postorder `D E B F C A`.

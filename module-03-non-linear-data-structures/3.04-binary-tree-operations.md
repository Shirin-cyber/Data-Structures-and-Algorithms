# 3.4 Binary Tree Operations

# 1. Binary Tree Traversal

**Traversing** a tree means **visiting every node exactly once**.

A binary tree can be traversed in **three different ways**, namely **Preorder, Postorder and Inorder**. The **order in which the nodes are visited** differs between these techniques.

```
Binary Tree Traversal
├── a. Inorder     (Left → Root → Right)
├── b. Preorder    (Root → Left → Right)
└── c. Postorder   (Left → Right → Root)
```

> **The big idea:** in all three, the **left subtree is always done before the right subtree**. The only thing that changes is **when the root is processed**:
> - **Pre**order: root **first** (pre = before)
> - **In**order: root **in the middle** (in = between)
> - **Post**order: root **last** (post = after)

### The tree used in the examples

```
          A
         / \
        B   C
       / \   \
      D   E   F
```

Here `R` in the steps below means the **root of the tree (or subtree)** we're currently working on. Every traversal is **recursive**: when it says "traverse the left subtree", we apply the same three steps to that smaller tree.

---

## a. Inorder Traversal

The traversal operation is done by:

1. **Traverse the left subtree** of R
2. **Process the root** R
3. **Traverse the right subtree** of R

**Result for the example tree: `D B E A C F`**

How it works, step by step:

```
Inorder(A)
├── Inorder(B)                  ← left subtree of A
│   ├── Inorder(D)              ← left of B
│   │     (D has no left)  → process D
│   │     (D has no right)
│   ├── process B               ← root B
│   └── Inorder(E)              ← right of B
│         process E
├── process A                   ← root A
└── Inorder(C)                  ← right subtree of A
    ├── (C has no left)
    ├── process C
    └── Inorder(F)
          process F

Output:  D  B  E  A  C  F
```

### Algorithm (recursive)

```
Inorder(R)
Step 1: If R = NULL, then return
Step 2: Inorder(left subtree of R)
Step 3: Process R (print its data)
Step 4: Inorder(right subtree of R)
```

---

## b. Preorder Traversal

Preorder traversal is also known as **Depth-first traversal**. The traversal operation is done by:

1. **Process the root** R
2. **Traverse the left subtree** of R
3. **Traverse the right subtree** of R

**Result for the example tree: `A B D E C F`**

```
Preorder(A)
├── process A                   ← root first
├── Preorder(B)
│   ├── process B
│   ├── Preorder(D) → process D
│   └── Preorder(E) → process E
└── Preorder(C)
    ├── process C
    └── Preorder(F) → process F

Output:  A  B  D  E  C  F
```

> **About "depth-first":** all three traversals go **deep** into the tree (down one branch) before moving across to the next branch, so strictly they are all depth-first. Preorder is the one that follows the usual depth-first order starting from the root, which is why it's often the one called depth-first traversal. Use whichever wording your syllabus uses.

### Algorithm (recursive)

```
Preorder(R)
Step 1: If R = NULL, then return
Step 2: Process R (print its data)
Step 3: Preorder(left subtree of R)
Step 4: Preorder(right subtree of R)
```

---

## c. Postorder Traversal

The operation is done by:

1. **Traverse the left subtree** of R
2. **Traverse the right subtree** of R
3. **Process the root** R

**Result for the example tree: `D E B F C A`**

```
Postorder(A)
├── Postorder(B)
│   ├── Postorder(D) → process D
│   ├── Postorder(E) → process E
│   └── process B               ← B comes after its children
├── Postorder(C)
│   ├── Postorder(F) → process F
│   └── process C
└── process A                   ← root last

Output:  D  E  B  F  C  A
```

### Algorithm (recursive)

```
Postorder(R)
Step 1: If R = NULL, then return
Step 2: Postorder(left subtree of R)
Step 3: Postorder(right subtree of R)
Step 4: Process R (print its data)
```

---

## Comparing the Three

| Traversal | Order | When is the root processed? | Result for the example tree |
|-----------|-------|-----------------------------|-----------------------------|
| **Inorder** | Left, Root, Right | Between the subtrees | `D B E A C F` |
| **Preorder** | Root, Left, Right | Before the subtrees | `A B D E C F` |
| **Postorder** | Left, Right, Root | After the subtrees | `D E B F C A` |

## Traversals in C 

```c
struct node {
    char data;
    struct node *left;
    struct node *right;
};

void inorder(struct node *root) {
    if (root == NULL) return;
    inorder(root->left);
    printf("%c ", root->data);
    inorder(root->right);
}

void preorder(struct node *root) {
    if (root == NULL) return;
    printf("%c ", root->data);
    preorder(root->left);
    preorder(root->right);
}

void postorder(struct node *root) {
    if (root == NULL) return;
    postorder(root->left);
    postorder(root->right);
    printf("%c ", root->data);
}
```

The three functions are identical except for **where the `printf` line sits**.

## Connection to Expression Trees 

Remember the expression tree for `(a + b) * c` from 3.2?

```
        *
       / \
      +   c
     / \
    a   b
```

Traversing it gives the three notations from Polish notation:

| Traversal | Result | Notation |
|-----------|--------|----------|
| **Inorder** | `a + b * c` *(brackets are lost)* | Infix |
| **Preorder** | `* + a b c` | Prefix |
| **Postorder** | `a b + c *` | Postfix |

> There's also a fourth way, **level order traversal**, which visits the nodes level by level, from top to bottom and left to right. It uses a **queue**. For the example tree, it gives `A B C D E F`.

---

## Quick Revision

- **Traversal** = visiting every node exactly once.
- **Inorder:** Left → Root → Right.
- **Preorder:** Root → Left → Right. Also known as depth-first traversal.
- **Postorder:** Left → Right → Root.
- In all three, left comes before right. Only the position of the root changes.
- Example tree: Inorder `D B E A C F`, Preorder `A B D E C F`, Postorder `D E B F C A`.

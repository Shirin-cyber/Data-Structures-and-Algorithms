# 3.9 Representation of Graph

A graph can be represented in **two ways**:

```
Representation of Graph
├── 1. Sequential representation (Adjacency Matrix)
└── 2. Linked list representation
```

We'll use this graph for the examples:

```
      A
     / \
    B───C───D
```

Nodes: `A, B, C, D`. Edges: `(A,B)`, `(A,C)`, `(B,C)`, `(C,D)`.

---

# 1. Sequential Representation (Adjacency Matrix)

A graph with **n nodes** can be represented by an **n × n square matrix**, with the **row and column numbers representing the vertices**.

- Each cell at the crossing of two vertices can only have the value **0 or 1**.
- The entry in the adjacency matrix **[vi, vj] = 1** only if there **exists an edge from vi to vj**. Otherwise, it's **0**.

### Example (undirected graph)

|   | A | B | C | D |
|---|---|---|---|---|
| **A** | 0 | 1 | 1 | 0 |
| **B** | 1 | 0 | 1 | 0 |
| **C** | 1 | 1 | 0 | 1 |
| **D** | 0 | 0 | 1 | 0 |

How to read it: the cell at row **A**, column **B** is `1`, so there's an edge between A and B. The cell at row **A**, column **D** is `0`, so there's no edge between A and D.

### Things to notice 

- The **diagonal is all 0s**, since no node has a loop here (a loop would put a `1` on the diagonal).
- For an **undirected** graph the matrix is **symmetric** (the same on both sides of the diagonal), because an edge `(A,B)` works both ways.
- The **sum of a row** gives the **degree** of that node. Row C: `1 + 1 + 0 + 1 = 3` ✓

### Directed graph

For a directed graph, `[vi, vj] = 1` only if there's an edge **from vi to vj**, so the matrix is **not necessarily symmetric**.

Edges: `A → B`, `A → C`, `B → C`, `C → D`

|   | A | B | C | D |
|---|---|---|---|---|
| **A** | 0 | 1 | 1 | 0 |
| **B** | 0 | 0 | 1 | 0 |
| **C** | 0 | 0 | 0 | 1 |
| **D** | 0 | 0 | 0 | 0 |

- **Row sum** = **outdegree** (A has 2, D has 0)
- **Column sum** = **indegree** (A has 0, C has 2)

### Weighted graph

For a weighted graph, we store the **weight** of the edge in the cell instead of `1`.

### In C

```c
int adj[4][4] = {0};     // 4 nodes, all entries start as 0

adj[0][1] = 1;           // edge from node 0 (A) to node 1 (B)
adj[1][0] = 1;           // for an undirected graph, set the other side too
```

# 2. Linked List Representation

The linked list representation of a graph contains **2 lists**:

- **a. Node list**
- **b. Edge list** (adjacency list)

### Node list

Each element in the node list corresponds to **a node in the graph**. It contains:

- the **name** of the node
- a **pointer to the adjacent node(s)**, which points to the first element of that node's edge list
- a **pointer to the next node** in the node list

```
 ┌──────┬────────────┬─────────────┐
 │ NAME │ NEXT NODE  │ ADJ (first  │
 │      │            │ edge)       │
 └──────┴────────────┴─────────────┘
```

### Edge list

Each element in the edge list represents **an edge of the graph**. It contains:

- the **destination node** of the edge
- a **link** that connects together the edges with the **same initial node**

```
 ┌───────────────┬──────────────────┐
 │ DESTINATION   │ NEXT EDGE (same  │
 │ NODE          │ initial node)    │
 └───────────────┴──────────────────┘
```

### Example (same undirected graph)

```
 Node list           Edge list
┌───┐
│ A │ ──────────────► [B|●]──►[C|NULL]
├───┤
│ B │ ──────────────► [A|●]──►[C|NULL]
├───┤
│ C │ ──────────────► [A|●]──►[B|●]──►[D|NULL]
├───┤
│ D │ ──────────────► [C|NULL]
└───┘
```

How to read it: each row of the node list points to a chain of edges starting from that node. A's chain has two edges, to **B** and **C**. C's chain has three, to **A**, **B** and **D**.

In an **undirected** graph, each edge shows up **twice** (B is in A's chain, and A is in B's chain). In a **directed** graph, an edge `A → B` shows up only in **A's** chain.

### In C 

```c
struct edge {
    int dest;                 // destination node
    struct edge *next;        // next edge with the same initial node
};

struct vertex {
    char name;                // name of the node
    struct vertex *next;      // next node in the node list
    struct edge *adj;         // first edge starting from this node
};
```

# Matrix vs Linked List Representation 

| Basis | Adjacency Matrix | Linked List |
|-------|------------------|-------------|
| **Memory used** | `n × n` entries, always | Only nodes plus the edges that exist |
| **Checking if an edge exists** | Very fast, just look at one cell | Slower, need to go through the chain |
| **Best for** | **Dense** graphs (lots of edges) | **Sparse** graphs (few edges) |
| **Adding or removing nodes** | Difficult (the matrix size is fixed) | Easy |

> **Connection to 1.8:** the matrix of a graph with few edges is mostly 0s, which makes it a **sparse matrix** that wastes memory. That's why linked lists are the better choice for sparse graphs.

---

# Quick Revision

- A graph can be represented using the **sequential (adjacency matrix)** or the **linked list** representation.
- **Adjacency matrix:** an `n × n` matrix, with `[vi, vj] = 1` only if there's an edge from `vi` to `vj`, otherwise `0`.
- **Linked list:** a **node list** (name, pointer to adjacent nodes, pointer to next node) and an **edge list** (destination node, link to the next edge with the same initial node).
- Matrix: quick edge lookup but uses `n × n` memory. Linked list: saves memory for sparse graphs.

# 3.3 Representation of Binary Trees

Binary trees can be represented using either:

1. An **array**, or
2. A **linked list**

---

# a. Array Representation

The simplest technique for representing a binary tree is to store the elements using a **1D array**. This is also called a **sequential representation**.

### Rules for a sequential binary tree

- The **root** of the tree is stored in `TREE[0]`.
- If an element is stored in `TREE[K]`, then:
  - its **left child** is stored in `TREE[2K + 1]`
  - its **right child** is stored in `TREE[2K + 2]`

> Going the other way, the **parent** of the element in `TREE[K]` is in `TREE[(K - 1) / 2]` (integer division), for `K > 0`.

### Example

```
          A
         / \
        B   C
       / \  /
      D  E F
```

Stored in an array:

| Index | 0 | 1 | 2 | 3 | 4 | 5 |
|-------|---|---|---|---|---|---|
| **TREE** | A | B | C | D | E | F |

Checking the rules:

- A is at `K = 0`. Left child at `2(0)+1 = 1` (B). Right child at `2(0)+2 = 2` (C).
- B is at `K = 1`. Left child at `2(1)+1 = 3` (D). Right child at `2(1)+2 = 4` (E).
- C is at `K = 2`. Left child at `2(2)+1 = 5` (F). Right child at `2(2)+2 = 6`, which is empty (C has no right child).

### Drawback of array representation 

This works well for **complete binary trees**, since there are no gaps. But for trees with missing nodes, like a **skewed tree**, a lot of space is wasted.

```
  A
   \
    B          Right skewed tree with 3 nodes
     \
      C
```

| Index | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|-------|---|---|---|---|---|---|---|
| **TREE** | A | | B | | | | C |

Only 3 nodes, but the array needs 7 positions, and 4 of them are empty.

---

# b. Linked List Representation

Every node in the linked list representation of a binary tree contains **three parts**:

- the **data element**
- a **pointer to the left node**
- a **pointer to the right node**

```
 ┌──────┬──────┬───────┐
 │ LEFT │ DATA │ RIGHT │
 └──────┴──────┴───────┘
```

The root node is pointed to by a pointer called **ROOT**. The tree is **empty if `ROOT = NULL`**.

```
                 ROOT
                   │
                   ▼
             ┌─────┬───┬─────┐
             │  ●  │ A │  ●  │
             └──┬──┴───┴──┬──┘
        ┌───────┘         └───────┐
        ▼                         ▼
  ┌──────┬───┬──────┐      ┌──────┬───┬──────┐
  │ NULL │ B │ NULL │      │ NULL │ C │ NULL │
  └──────┴───┴──────┘      └──────┴───┴──────┘
```

A node in C looks like this 

```c
struct node {
    int data;
    struct node *left;
    struct node *right;
};

struct node *root = NULL;     // NULL means the tree is empty
```

A node with no left child has `left = NULL`, and a node with no right child has `right = NULL`. A leaf node has both as `NULL`.

---

# Array vs Linked List Representation 

| Basis | Array | Linked List |
|-------|-------|-------------|
| **Finding children** | Using the formulas `2K+1` and `2K+2` | Using the left and right pointers |
| **Memory** | Wasted for trees with missing nodes (like skewed trees) | Only the nodes that exist take memory, but each node needs two extra pointers |
| **Size** | Fixed in advance | Grows and shrinks as nodes are added or removed |
| **Insertion / deletion** | Difficult, may need elements moved around | Easy, only pointers change |
| **Best for** | Complete binary trees | Any binary tree |

---

# Quick Revision

- A binary tree can be represented using an **array** or a **linked list**.
- **Array:** root at `TREE[0]`. For the element at `TREE[K]`, left child is at `TREE[2K+1]` and right child at `TREE[2K+2]`.
- Array representation wastes space when the tree has many missing nodes.
- **Linked list:** each node has **data, a left pointer and a right pointer**.
- The root is pointed to by `ROOT`, and the tree is empty when `ROOT = NULL`.

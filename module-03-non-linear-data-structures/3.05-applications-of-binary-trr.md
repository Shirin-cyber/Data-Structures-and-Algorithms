# 3.5 Applications of Binary Trees

A binary tree is useful whenever data can be **split into two choices at each step**, or whenever data has a **parent-and-two-children** shape. Here are the main places it's used.

```
Applications of Binary Trees
├── Binary Search Tree (searching and sorting)
├── Expression Trees (parsing and evaluating expressions)
├── Heaps (priority queues and heap sort)
├── Huffman Coding (data compression)
├── Decision Trees (making decisions step by step)
└── Routing (finding where to send data)
```

---

## 1. Binary Search Tree (BST): searching and sorting

A **Binary Search Tree** is a binary tree arranged by a simple rule:

- everything in the **left** subtree is **smaller** than the node
- everything in the **right** subtree is **bigger** than the node

```
          50
         /  \
       30    70
      /  \   / \
    20   40 60  80
```

**Why it's useful:** to search for a value, you start at the root and at each step go **left or right**, ignoring the other half. This makes searching much faster than checking every item one by one.

> **Think of it like this:** guessing a number between 1 and 100 where your friend only says "higher" or "lower". Every guess cuts the options roughly in half. A BST does the same thing.

**Sorting bonus:** if you do an **inorder traversal** (from 3.4) of a BST, you get the values in **sorted order**. For the tree above: `20 30 40 50 60 70 80`.

> **Note:** a BST is fast only when it's reasonably balanced. If it turns into a **skewed tree** (a straight line), it becomes as slow as a linked list.

---

## 2. Expression Trees: parsing and evaluating expressions

An **expression tree** stores a maths expression, with operators as internal nodes and operands as leaves.

```
        *
       / \
      +   c        ←  (a + b) * c
     / \
    a   b
```

**Where it's used:**

- **Compilers** use a similar tree (a **syntax tree**) to understand the code you write before running it.
- **Calculators** can use it to work out the correct order of operations without needing brackets.
- Traversing it gives **infix, prefix and postfix** forms of the expression.

---

## 3. Heaps: priority queues and heap sort

A **heap** is a special kind of **complete binary tree** where each parent is **bigger (or smaller) than its children**. The biggest (or smallest) item is always at the root, so it can be picked quickly.

```
          90          ← biggest is always at the top
         /  \
       70    80
      /  \
    30    60
```

**Where it's used:**

- **Priority queues:** a queue where the **most important item** comes out first, not the oldest. For example, an operating system picking the most urgent task to run next.
- **Heap sort:** a sorting method built on this idea.

---

## 4. Huffman Coding: data compression

**Huffman coding** is a way to **shrink files**. Letters that appear **often** get **short codes**, and letters that appear **rarely** get **longer codes**. The codes are decided using a **binary tree**, where going left means `0` and going right means `1`.

```
         (root)
         0/   \1
        A      (  )
              0/  \1
              B    C
```

Here `A = 0`, `B = 10`, `C = 11`. The most common letter gets the shortest code.

**Where it's used:** the idea is used in compression formats like ZIP, and in image and audio compression.

---

## 5. Decision Trees: making decisions step by step

A decision tree asks a **yes/no question** at each node and goes left or right depending on the answer, until it reaches a result at a leaf.

```
         Is it raining?
          /          \
        Yes           No
         |             |
   Take umbrella   Is it sunny?
                    /       \
                  Yes        No
                   |          |
             Wear sunglasses  Go as usual
```

**Where it's used:** games like "20 questions", troubleshooting guides, and in **machine learning**, where decision trees are used to make predictions.

---

## 6. Routing: finding where to send data

Routers need to decide where to send each piece of data, based on its IP address. IP addresses are made of **bits (0s and 1s)**, so a **binary tree-like structure** can be used to match an address bit by bit (go left on `0`, right on `1`) and find the right route quickly.

---

## Quick Revision

| Application | What the binary tree does |
|-------------|---------------------------|
| **Binary Search Tree** | Fast searching by going left or right. Inorder traversal gives sorted data |
| **Expression tree** | Stores expressions for compilers and calculators |
| **Heap** | Keeps the biggest (or smallest) item at the top, for priority queues and heap sort |
| **Huffman coding** | Gives shorter codes to common letters, for compression |
| **Decision tree** | Makes yes/no decisions step by step |
| **Routing** | Matches addresses bit by bit to find the route |

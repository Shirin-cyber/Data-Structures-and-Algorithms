# 3.6 Properties of Binary Trees

These are the facts and formulas that are always true for binary trees. They're handy for exam questions, and they're easy once you see **why** they work.

> **Conventions used here (same as 3.1):**
> - The **root is on level 0**.
> - The **height** of a tree is counted in **edges** (a tree with only a root has height 0).
> - `n` = total number of nodes, `h` = height, `L` = level.
>
> Some books count the root as level 1 and height as the number of levels, which changes the formulas slightly. See the table at the end and follow your syllabus.

---

## Property 1: Maximum nodes at level L

A binary tree has at most **`2^L`** nodes on level `L`.

**Why:** every node can have at most 2 children, so each level can **at most double** the one above it.

| Level | Maximum nodes |
|-------|---------------|
| 0 | 1 |
| 1 | 2 |
| 2 | 4 |
| 3 | 8 |
| L | 2^L |

```
Level 0:            ●                    1 node
                  /   \
Level 1:         ●     ●                 2 nodes
                / \   / \
Level 2:       ●   ● ●   ●               4 nodes
```

---

## Property 2: Maximum nodes in a tree of height h

A binary tree of height `h` has at most **`2^(h+1) − 1`** nodes in total.

**Why:** add up the maximum of every level: `1 + 2 + 4 + ... + 2^h = 2^(h+1) − 1`.

| Height h | Maximum nodes |
|----------|---------------|
| 0 | 1 |
| 1 | 3 |
| 2 | 7 |
| 3 | 15 |

A tree that actually has this many nodes (every level completely full) is called a **perfect binary tree**.

---

## Property 3: Minimum nodes in a tree of height h

A binary tree of height `h` has at least **`h + 1`** nodes.

**Why:** the thinnest tree is a **skewed tree**, a single chain, with one node on each level.

```
  A          h = 2
   \
    B        nodes = 3  = h + 1
     \
      C
```

Also, a tree with `n` nodes can have a **maximum height of `n − 1`** (the skewed case).

---

## Property 4: Minimum height for n nodes

The **smallest possible height** for a binary tree with `n` nodes is:

```
h(min) = ⌈ log₂(n + 1) ⌉ − 1
```

(`⌈ ⌉` means round **up** to the next whole number.)

**Why:** this comes from Property 2. To fit `n` nodes into the smallest height, we need `2^(h+1) − 1 ≥ n`.

| n (nodes) | Minimum height |
|-----------|----------------|
| 1 | 0 |
| 2 or 3 | 1 |
| 4 to 7 | 2 |
| 8 to 15 | 3 |

**Why it matters:** a **short, wide** tree is fast to search. A **tall, thin** tree is slow. That's why we like balanced trees.

---

## Property 5: Leaves and nodes with two children

If `n0` = number of **leaf nodes** (0 children) and `n2` = number of nodes with **exactly 2 children**, then:

```
n0 = n2 + 1
```

In words: **leaves = (nodes with two children) + 1**.

```
          A            n2: A and C have 2 children  →  n2 = 2
         / \
        B   C          n0: B, D and E are leaves    →  n0 = 3
           / \
          D   E        n0 = n2 + 1 = 2 + 1 = 3  ✓
```

**Why *(extra)*:** count the edges in two ways. Every node except the root has one edge coming into it, so edges = `n − 1`. Counting from the parents' side, a node with 1 child gives 1 edge (`n1` such nodes) and a node with 2 children gives 2 edges, so edges = `n1 + 2·n2`. Also `n = n0 + n1 + n2`. Putting these together gives `n0 = n2 + 1`.

---

## Property 6: Number of edges

A binary tree with `n` nodes has exactly **`n − 1` edges**.

**Why:** every node except the root has exactly **one parent edge**.

---

## Property 7: Full binary tree

In a **full binary tree** (every node has 0 or 2 children), if there are `i` internal nodes, then:

- number of **leaves** = `i + 1`
- **total nodes** = `2i + 1`

Using the tree from Property 5: internal nodes `i = 2` (A and C), leaves = 3, total = `2(2) + 1 = 5` ✓

---

## Property 8: Height of a complete binary tree

A **complete binary tree** with `n` nodes has height:

```
h = ⌊ log₂ n ⌋
```

(`⌊ ⌋` means round **down**.)

| n (nodes) | Height |
|-----------|--------|
| 1 | 0 |
| 2, 3 | 1 |
| 4 to 7 | 2 |
| 8 to 15 | 3 |

Example: the complete tree with 6 nodes (A, B, C, D, E, F) has height `⌊log₂ 6⌋ = 2` ✓

---

## Property 9: Null pointers in the linked representation *(extra)*

In the linked list representation (3.3), a binary tree with `n` nodes has exactly **`n + 1` null pointers**.

**Why:** the `n` nodes have `2n` pointer fields in total (a left and a right each). Only `n − 1` of them are used for edges, so `2n − (n − 1) = n + 1` are `NULL`.

Example: 3 nodes (A with children B and C) → 6 pointer fields, 2 used, **4 null** = `3 + 1` ✓

---

## If your book counts the root as level 1

Some books start levels at **1** and define height as the **number of levels**. The formulas then become:

| Property | Root at level 0, height in edges (used above) | Root at level 1, height in levels |
|----------|-----------------------------------------------|-----------------------------------|
| Max nodes at level L | `2^L` | `2^(L−1)` |
| Max nodes in tree of height h | `2^(h+1) − 1` | `2^h − 1` |
| Min nodes in tree of height h | `h + 1` | `h` |
| Min height for n nodes | `⌈log₂(n+1)⌉ − 1` | `⌈log₂(n+1)⌉` |

The **shape of the tree doesn't change**. Only the way of counting does.

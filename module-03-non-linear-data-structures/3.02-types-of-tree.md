# 1. Binary Tree

A binary tree is a special tree where **each node can have no more than two children**.

A non-empty binary tree consists of:

- a node called the **root node**
- a **left subtree**
- a **right subtree**

```
          A            ← root
         / \
        B   C          ← B is the left child, C is the right child
       / \
      D   E
```

The two children are called the **left child** and the **right child**, and the left and right subtrees are themselves binary trees.

## Types of Binary Tree

### a. Complete Binary Tree

A tree is said to be **complete** if:

- **All its levels, except possibly the last, must be completely filled**
- **All the leaf nodes must appear as far left as possible** (in the last level, nodes are filled from left to right with no gaps)

```
          A
         / \
        B   C
       / \  /
      D  E F          ← last level filled from the left, no gaps
```

### b. Full Binary Tree

A full binary tree is a special type of tree in which **the leaf nodes have zero children and all the other nodes have exactly two children**. So every node has either **0 or 2 children**, never just one.

```
          A
         / \
        B   C
           / \
          D   E       ← every node has 0 or 2 children
```

### Complete vs Full *(extra)*

| | Complete Binary Tree | Full Binary Tree |
|---|----------------------|------------------|
| **Rule** | All levels filled except possibly the last, which is filled from the left | Every node has 0 or 2 children |
| **Can a node have just one child?** | Yes, but at most one node (it sits on the second-last level and has only a left child) | No |

A tree can be one without being the other. In the examples above, the first tree is complete but not full (C has only one child), and the second is full but not complete (the last level has a gap on the left).

# 2. Skewed Tree

A skewed binary tree is a type of binary tree in which **all the nodes have only either one child or no child**.

### a. Left Skewed Binary Tree

A tree in which all the nodes have a **left child or no child at all**. It is a **left side dominated** tree, and the **right child remains null**.

```
        A
       /
      B
     /
    C
```

### b. Right Skewed Binary Tree

A tree in which all the nodes have a **right child or no child at all**. It is a **right side dominated** tree, and the **left child remains null**.

```
    A
     \
      B
       \
        C
```

> A skewed tree looks and behaves like a **linked list**, so searching through it is slow, since you have to go through the nodes one by one.

# 3. Expression Tree

An expression tree is a **binary tree** in which each **internal node corresponds to an operator** and each **leaf node corresponds to an operand**.

Example: the expression `(a + b) * c`

```
        *
       / \
      +   c
     / \
    a   b
```

The operators `*` and `+` are internal nodes. The operands `a`, `b` and `c` are leaves.

## Construction of Expression Tree

The tree is built from a **postfix expression** using a **stack**. Scan the postfix expression one character at a time:

- If the character is an **operand**, **PUSH** it onto the stack.
- If the character is an **operator**, **POP two values** from the stack and make them its **children**, then **push the current node** back onto the stack.

> **Which child is which:** the **first** value popped becomes the **right child**, and the **second** value popped becomes the **left child**.

At the end, the one node left in the stack is the **root** of the expression tree.

### Example: postfix `ab+c*`

| Character | Action | Stack (bottom → top) |
|-----------|--------|----------------------|
| `a` | operand, push | `a` |
| `b` | operand, push | `a`, `b` |
| `+` | operator: pop `b` (right), pop `a` (left), make node `+`, push it | `+(a, b)` |
| `c` | operand, push | `+(a, b)`, `c` |
| `*` | operator: pop `c` (right), pop `+(a, b)` (left), make node `*`, push it | `*( +(a, b), c )` |

The final node `*` is the root, and the tree is the one drawn above.

> Reading an expression tree in **inorder** gives the infix expression, in **preorder** gives the prefix expression, and in **postorder** gives the postfix expression.

# Quick Revision

- **Binary tree:** each node has at most two children. It consists of a root, a left subtree and a right subtree.
- **Complete binary tree:** all levels filled except possibly the last, with leaf nodes as far left as possible.
- **Full binary tree:** every node has either 0 or 2 children.
- **Skewed tree:** every node has one child or none. **Left skewed:** only left children. **Right skewed:** only right children.
- **Expression tree:** a binary tree where internal nodes are operators and leaves are operands.
- **Construction:** operand → push. Operator → pop two, make them its children, push the new node.

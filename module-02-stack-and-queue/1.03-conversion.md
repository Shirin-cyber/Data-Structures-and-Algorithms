# Conversion of Infix to Postfix

A **stack** is used to convert an infix expression into a postfix expression. The stack holds **operators and left brackets `(` only**. Operands never go on the stack, they go straight to the postfix expression.

---

## Operator Precedence

| Precedence | Operators | Order of evaluation |
|------------|-----------|---------------------|
| Highest | `^` (power) | Right to left |
| Middle | `*`, `/`, `%` | Left to right |
| Lowest | `+`, `-` | Left to right |

---

## Rules (what to do with each symbol)

Scan the infix expression **from left to right**, one symbol at a time.

| Symbol scanned | Action |
|----------------|--------|
| **Operand** (letter or number) | Add it directly to the postfix expression |
| **`(`** | Push it onto the stack |
| **`)`** | Pop operators from the stack and add them to the postfix expression **until `(` is found**. Then remove the `(` and discard it (it doesn't go to the postfix) |
| **Operator** | While the operator on top of the stack has **higher or equal precedence**, pop it to the postfix expression. Then push the scanned operator |
| **End of expression** | Pop everything left in the stack and add it to the postfix expression |

> **Two things to remember:**
> - A `(` on top of the stack is **never popped by an operator**. It only gets removed when a `)` comes.
> - For `^` (right to left), pop only when the top has **higher** precedence, not equal.

### Algorithm

```
Step 1: Start
Step 2: Scan the infix expression from left to right
Step 3: If the scanned symbol is an operand, add it to the postfix expression
Step 4: If the scanned symbol is '(', push it onto the stack
Step 5: If the scanned symbol is an operator
          While the stack is not empty and the top of the stack is an operator
          with higher or equal precedence (for '^', only if higher), pop it and
          add it to the postfix expression
          Push the scanned operator onto the stack
Step 6: If the scanned symbol is ')'
          Pop from the stack and add to the postfix expression until '(' is found
          Remove '(' from the stack
Step 7: Repeat Steps 3 to 6 until the whole expression is scanned
Step 8: Pop the remaining operators from the stack and add them to the postfix expression
Step 9: Stop
```

## Example 1: `(A+B)*C-D/E`

*(The stack is shown from bottom to top, so the rightmost symbol is the top.)*

| Infix scanned | Stack | Postfix expression |
|---------------|-------|--------------------|
| `(` | `(` | |
| `A` | `(` | `A` |
| `+` | `( +` | `A` |
| `B` | `( +` | `AB` |
| `)` | | `AB+` |
| `*` | `*` | `AB+` |
| `C` | `*` | `AB+C` |
| `-` | `-` | `AB+C*` |
| `D` | `-` | `AB+C*D` |
| `/` | `- /` | `AB+C*D` |
| `E` | `- /` | `AB+C*DE` |
| *end* | | `AB+C*DE/-` |

**Postfix expression: `AB+C*DE/-`**

What happened at the tricky steps:

- At `)`: `+` is popped to the postfix, and then `(` is removed.
- At `-`: the `*` on top has **higher** precedence than `-`, so `*` is popped first, then `-` is pushed.
- At `/`: the `-` on top has **lower** precedence than `/`, so `/` is just pushed on top.
- At the end: the stack is emptied from the top, so `/` goes out first, then `-`.

## Example 2: `A+(B*C-(D/E^F)*G)*H`

This one has nested brackets and a power operator, so it covers every rule.

| Infix scanned | Stack | Postfix expression |
|---------------|-------|--------------------|
| `A` | | `A` |
| `+` | `+` | `A` |
| `(` | `+ (` | `A` |
| `B` | `+ (` | `AB` |
| `*` | `+ ( *` | `AB` |
| `C` | `+ ( *` | `ABC` |
| `-` | `+ ( -` | `ABC*` |
| `(` | `+ ( - (` | `ABC*` |
| `D` | `+ ( - (` | `ABC*D` |
| `/` | `+ ( - ( /` | `ABC*D` |
| `E` | `+ ( - ( /` | `ABC*DE` |
| `^` | `+ ( - ( / ^` | `ABC*DE` |
| `F` | `+ ( - ( / ^` | `ABC*DEF` |
| `)` | `+ ( -` | `ABC*DEF^/` |
| `*` | `+ ( - *` | `ABC*DEF^/` |
| `G` | `+ ( - *` | `ABC*DEF^/G` |
| `)` | `+` | `ABC*DEF^/G*-` |
| `*` | `+ *` | `ABC*DEF^/G*-` |
| `H` | `+ *` | `ABC*DEF^/G*-H` |
| *end* | | `ABC*DEF^/G*-H*+` |

**Postfix expression: `ABC*DEF^/G*-H*+`**

What happened at the tricky steps:

- At `-`: the `*` on top has higher precedence, so it's popped. The `(` below it stops the popping, so `-` is pushed on top of the `(`.
- At `^`: it has higher precedence than `/`, so it's pushed on top without popping anything.
- At the first `)`: `^` and `/` are popped in that order, then the inner `(` is removed.
- At the second `)`: `*` and `-` are popped, then that `(` is removed. Only `+` stays in the stack.
- At the last `*`: the `+` on top has lower precedence, so `*` is pushed on top.

---

## Quick Revision

- Scan **left to right**. The stack holds only **operators and `(`**.
- **Operand** → straight to the postfix expression.
- **`(`** → push.
- **`)`** → pop until `(`, then discard the `(`.
- **Operator** → pop while the top has higher or equal precedence, then push.
- **End** → pop everything left.
- Precedence: `^` highest, then `*` `/` `%`, then `+` `-`.

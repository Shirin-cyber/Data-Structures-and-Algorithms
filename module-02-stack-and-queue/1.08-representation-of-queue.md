# 2.8 Representation of Queue

A queue is usually represented using:

1. A **linear array**, or
2. A **one way (singly) linked list**

---

# Array Representation of Queue

A queue can be represented using a **linear array** of elements and the variables **FRONT**, **REAR** and **MAX**.

- **FRONT:** index of the front element (where deletion happens)
- **REAR:** index of the last element (where insertion happens)
- **MAX:** the maximum size of the array

```
Index:     0     1     2     3     4        MAX = 5
        ┌─────┬─────┬─────┬─────┬─────┐
QUEUE = │ 10  │ 20  │ 30  │     │     │
        └─────┴─────┴─────┴─────┴─────┘
           ▲           ▲
         FRONT = 0   REAR = 2
```

### Conditions

| State | Condition |
|-------|-----------|
| **Empty** | `FRONT = -1` or `FRONT > REAR` |
| **Full** | `FRONT = 0` and `REAR = MAX - 1` |

> **Note:** an empty queue starts with `FRONT = REAR = -1`. After the last element is deleted, FRONT moves past REAR (`FRONT = REAR + 1`), which also means empty.

### Algorithm

The algorithm for this representation is the same as the **insertion (Enqueue) algorithm of a queue**:

```
Step 1: Start
Step 2: If REAR = MAX - 1
          Print "Queue overflow"
          Go to Step 5
Step 3: If FRONT = -1 and REAR = -1
          Set FRONT = REAR = 0
        Else
          Set REAR = REAR + 1
Step 4: Set QUEUE[REAR] = ITEM
Step 5: Exit
```

# Linked List Representation of Queue

The **disadvantage** of using an array to represent a queue is that the array must be specified to have a **fixed size**. If the array size cannot be known ahead of time, the **linked list representation** is used.

- The **head pointer** of the linked list is used as **FRONT**.
- Another pointer called **REAR** is used to store the **address of the last element** of the queue.

```
 FRONT                                   REAR
   │                                       │
   ▼                                       ▼
┌──────┬──────┐   ┌──────┬──────┐   ┌──────┬──────┐
│  10  │  ●───┼─► │  20  │  ●───┼─► │  30  │ NULL │
└──────┴──────┘   └──────┴──────┘   └──────┴──────┘
```

- Insertion (**enqueue**) happens at the **rear** end.
- Deletion (**dequeue**) happens at the **front** end.
- When the queue is empty, `FRONT = NULL` (and `REAR = NULL`).

### Algorithm for Enqueue (linked list)

```
Step 1: Create a new node
Step 2: Store the given value in the new node
Step 3: Set NEWNODE -> NEXT = NULL
Step 4: If the queue is empty (FRONT = NULL)
          Set both FRONT and REAR to the new node
Step 5: Otherwise
          Set REAR -> NEXT = NEWNODE
          Update REAR = NEWNODE
Step 6: Stop
```

How it works: the new node always goes **after the current last node** (`REAR -> NEXT`), and then REAR moves to the new node so it keeps pointing at the end.

### Algorithm for Dequeue (deletion from linked queue)

```
Step 1: Check whether the queue is empty (FRONT = NULL)
Step 2: If the queue is empty, return "Underflow"
Step 3: Store the front node in a temporary variable TEMP
Step 4: Move FRONT to the next node (FRONT = FRONT -> NEXT)
Step 5: If FRONT = NULL, set REAR = NULL
Step 6: Store the value of TEMP -> DATA in a variable
Step 7: Delete the temporary node
Step 8: Return the deleted value
Step 9: Stop
```

How it works: `TEMP` keeps hold of the old front node so it can be freed after FRONT has moved on. Step 5 matters because when the **last** element is removed, REAR would otherwise still point to a deleted node.

### C code

```c
#include <stdio.h>
#include <stdlib.h>

struct node {
    int data;
    struct node *next;
};

struct node *front = NULL;
struct node *rear = NULL;

void enqueue(int item) {
    struct node *newnode = (struct node *) malloc(sizeof(struct node));
    newnode->data = item;
    newnode->next = NULL;

    if (front == NULL) {            // queue is empty
        front = rear = newnode;
    } else {
        rear->next = newnode;
        rear = newnode;
    }
}

int dequeue() {
    if (front == NULL) {
        printf("Underflow\n");
        return -1;
    }
    struct node *temp = front;
    front = front->next;
    if (front == NULL)              // last element removed
        rear = NULL;
    int item = temp->data;
    free(temp);
    return item;
}
```

# Array vs Linked List Representation of Queue

| Basis | Array | Linked List |
|-------|-------|-------------|
| **Size** | Fixed (`MAX`), must be known in advance | Not fixed, grows and shrinks as needed |
| **Memory** | Unused space can be wasted | Extra memory needed for the next pointer in each node |
| **Full condition** | `REAR = MAX - 1` | Only when the system runs out of memory |
| **Empty condition** | `FRONT = -1` or `FRONT > REAR` | `FRONT = NULL` |

---

# Quick Revision

- A queue is usually represented using a **linear array** or a **one way linked list**.
- **Array:** uses FRONT, REAR and MAX. Fixed size is the disadvantage.
- **Linked list:** used when the size isn't known ahead of time. The head pointer is **FRONT**, and a separate **REAR** pointer holds the address of the last element.
- **Enqueue** at the rear, **dequeue** from the front.
- In linked list dequeue, if FRONT becomes `NULL`, also set `REAR = NULL`.

# Applications of Stack

- Evaluating expressions
- Conversion between expressions
- Backtracking
- Recursion removal
- Tree and graph traversal

Some more detail on each:

- **Evaluating expressions:** a stack is used to hold operands while an expression (like a postfix expression) is evaluated.
- **Conversion between expressions:** a stack is used to convert an expression from one notation to another, like infix to postfix.
- **Backtracking:** going back to a previous step when you hit a dead end, like solving a maze or the undo feature in an editor. The stack remembers the steps taken.
- **Recursion removal:** function calls already use a stack internally. A recursive program can be rewritten without recursion by using a stack of our own.
- **Tree and graph traversal:** depth-first traversal uses a stack to remember where to go back to.

> Stacks are also used for checking balanced brackets `( ) { } [ ]` and for parsing in compilers.

# Polish Notation

Algebraic expressions can be written using **3 separate but equivalent notations**, namely:

1. **Infix**
2. **Postfix**
3. **Prefix**

All three mean the same thing. They only differ in **where the operator is placed** relative to its operands.

```
Infix     →   a + b      operator in the middle
Prefix    →   + a b      operator before the operands
Postfix   →   a b +      operator after the operands
```

> **Where the name comes from:** prefix notation is called **Polish notation**, after the Polish mathematician Jan Łukasiewicz. Postfix is its reverse, so it's called **Reverse Polish Notation (RPN)**.

---

## Infix Notation

The operator symbol is placed **between its two operands**, as in most arithmetic operations. This is called an **infix expression**.

Example: `a + b`

This is the way we normally write maths, but it has a problem for computers. For an expression like `a + b * c`, we need **precedence rules** (multiplication before addition) and **brackets** to decide what to do first.

### Operator precedence 

| Precedence | Operators |
|------------|-----------|
| Highest | `^` (power) |
| Middle | `*`, `/`, `%` |
| Lowest | `+`, `-` |

Operators of the same level are usually evaluated **left to right** (except `^`, which goes right to left).

---

## Prefix Notation

Computers find prefix and postfix expressions easier to work with. In **prefix notation**, the operator is placed **before its two operands**.

Example: `+ab`

---

## Postfix Notation (Reverse Polish Notation)

In **postfix notation**, the operator is placed **after the operands**.

Example: `ab+`

---

## Comparing the Three

| Infix | Prefix | Postfix |
|-------|--------|---------|
| `a + b` | `+ab` | `ab+` |
| `a + b * c` | `+a*bc` | `abc*+` |
| `(a + b) * c` | `*+abc` | `ab+c*` |

Notice that in prefix and postfix, there are **no brackets**, and yet the order of operations is clear.

### Why use prefix and postfix?

- **No brackets needed.** The position of the operators already shows the order.
- **No precedence rules needed.** The expression is already arranged in the order it has to be calculated.
- **Easy for a computer to evaluate** with a stack, in a single pass.

### A quick look at how a stack helps 

Evaluating the postfix expression `2 3 4 * +` (which is `2 + 3 * 4`):

| Symbol read | Action | Stack (bottom → top) |
|-------------|--------|----------------------|
| `2` | push | 2 |
| `3` | push | 2, 3 |
| `4` | push | 2, 3, 4 |
| `*` | pop 4 and 3, multiply, push result | 2, 12 |
| `+` | pop 12 and 2, add, push result | 14 |

The answer is `14`, left on the stack.

## Quick Revision

- Stack applications: **evaluating expressions, conversion between expressions, backtracking, recursion removal, tree and graph traversal.**
- Expressions can be written in **infix, postfix and prefix**, and all three are equivalent.
- **Infix:** operator **between** the operands (`a+b`).
- **Prefix:** operator **before** the operands (`+ab`).
- **Postfix (Reverse Polish Notation):** operator **after** the operands (`ab+`).
- Prefix and postfix don't need brackets or precedence rules, which makes them easier for computers.
